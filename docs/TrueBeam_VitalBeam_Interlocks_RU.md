# Интерлоки, ошибки и устранение неисправностей TrueBeam/VitalBeam

> **ВАЖНО:** Публичные источники. Не заменяет официальные сервисные руководства Varian/Siemens Healthineers (MyVarian). Пункты ⚠️ основаны на родственном оборудовании (Clinac iX) и могут иметь иные обозначения на TrueBeam. Конкретные коды и точные сервисные последовательности — только по официальным руководствам.

---

## 1. Четыре петли разрешения (Enable Loops)

Вся защита строится на четырёх аппаратно-программных цепях; разрыв любой немедленно блокирует функцию.

| Аббревиатура | Цепь | При разрыве |
|---|---|---|
| **BEL** | Beam Enable Loop (MV-пучок) | Нет MV-пучка |
| **PEL** | Power Enable Loop (питание) | Снимается питание; машина не включается |
| **MEL** | Motion Enable Loop (движение) | Все оси остановлены |
| **kVBEL** | kV Beam Enable Loop | Нет kV-пучка (визуализация) |

Принцип: «Closed loop = safe to operate». Диагностика начинается с определения, какая цепь разомкнута.

## 2. Категории неисправностей (по анализу логов TrueBeam)
Визуализация (kV/MV/CBCT); MLC; генерация пучка (RF/модулятор/пушка/вакуум); охлаждение; ПО/сеть; стол (PSA); аксессуары; прочее. У TrueBeam примерно вдвое больше сбоев MLC/визуализации/генерации на фракцию vs Halcyon (нагрузка SBRT/SRS). [PMC8245652]

## 3–12. Ключевые интерлоки подсистем

- **VAC1/VAC2** — потеря вакуума (рост тока насоса) → STANDBY/блокировка. Волновод ~10⁻⁷–10⁻⁸ Торр; нарушение → arcing.
- **GAS** — давление SF₆ в волноводе <32 psi (защита от ВЧ-пробоя).
- **AIR** — низкое давление пневмовоздуха (приводы мишени/карусели/фольг/переключателя энергии).
- **PUMP** — температура/уровень воды вне допуска (минор >45°C, мажор >48°C). Система держит 40±5°C; нестабильность → детюнинг волновода. Утром, на холодной машине, наиболее вероятен.
- **FLOW** — перегрев изгибающего магнита / низкий уровень масла клистрона.
- **KSOL** — снижена мощность соленоида клистрона.
- **AFC (Automatic Frequency Control)** — держит резонанс волновода ~2856 МГц (±1 МГц); сбой проявляется как открытие BEL.
- **GFIL** ⚠️ — напряжение накала/смещения пушки ниже нормы → нет электронного пучка.
- **HVCB** ⚠️ — неисправность модулятора (ВВ-автовыключатель/тиратрон) → нет ВЧ-импульса.
- **BMAG** ⚠️ — напряжение ±5% / ток ±1% от нормы; **фиксирующийся** (latching) — нужен явный сброс.
- **CARR** ⚠️ — ошибка позиционирования карусели (фольги/мишень/фильтры).

## 12. Дозиметрические интерлоки
Сегментированные Kapton-камеры в головке; измеряют дозу, мощность, плоскостность, симметрию.

| Код | Канал | Триггер |
|---|---|---|
| **DOS1** | MU1 | Накопленные MU = preset (конец/остановка) |
| **DOS2** | MU2 | Вторичный канал >10% или +25 MU (защита от передоза) |
| **EXQ1/EXQ2** ⚠️ | Симметрия | Отклонение симметрии >2% (радиальный/трансверсальный) |
| **212022/212023** | MU-камера (TrueBeam) | Flatness Radial/Transverse >10% |

Ресурс MU-камеры ~14 млн клинических MU (~4,75 года); коды 212022/212023 — ранние признаки истощения (потеря давления). [PMC8664141]

## 13. BGM/GBM (Beam Generation Module) — TrueBeam
Сбой GBM открывает BEL → нет MV-пучка. Принцип сброса (публичный источник): Service Mode (Physicist) → Network → BGM → Power Cycle → Clear All → Time Delay (дождаться зелёного и отсчёта) → инициализировать MLC и Carousel → проверить тест-пучком. ⚠️ Первопричины GBM в открытых источниках не описаны.

## 14. Стол (Couch/PSA)
**CCHU/CCHL** — сбой верхней/нижней оси. Сброс (Advanced Options, обычно физик/FSE): Service Mode → Network → Couch Upper/Lower → Power Cycle → Clear → Treatment → проверить движение.

## 15. Защита от столкновений
- **LaserGuard II** — ИК-сканер у коллиматора, V-плоскость; немедленная остановка при объекте в зоне. Сброс — кнопка Collision Reset в комнате после устранения препятствия.
- **Machine Motion Model** — программная 3D-модель столкновений.
- Ёмкостный слой и физические пластины на kV-«плечах»; Zone Rules (программные ограничения комбинаций движений).

## 16. Дверной интерлок
Излучение ВКЛ → дверь не открыть; дверь открыта → пучок не запустить. Два независимых переключателя разного принципа. Проверяется при каждом утреннем КО.

## 17. MLC-интерлоки
Крупнейшая категория. Причины: отказ двигателя листа, ошибка позиции, отказ двигателя джо. Анализ Trajectory Logs предсказывает отказ двигателя листа за 1–3 дня. [PMC8245652, ScienceDirect S2405631620300452]

## 18. Аксессуары (страница 5 Event Log)
IM (Interface Mount), AM (Accessory Mount), EA (Electron Applicator), CM (Compensator Mount), CTRL (Accessory Controller). Несовпадение Secondary≠Primary → проблема установки; снимается после корректной установки.

## 20. Журналы (Event Log / Trajectory Logs)
- **Event Log** по страницам: (1) параметры машины в момент сбоя; (2) активные интерлоки + статусы **DS** (disabled) / **HS** (hardware set) / **AC** (active) / **LA** (latched); (5) аксессуары; (6) Error Summary (HWFA/CTRL/MOTN). Пример: «Controller interlock: CPU Beam ON/OFF failed while trying beam ON» = кнопка Beam-On не удержана.
- **Trajectory Logs** — ожидаемые vs фактические позиции (коллиматор/гантри/джо/MLC/MU) каждые 20 мс; предиктивное обслуживание.

## 21. Service Mode — уровни доступа
- **Basic** (физик): абсолютная калибровка, сброс интерлоков, базовая настройка пучка.
- **Intermediate**: калибровка осей, настройка пучка, большинство сервисных функций.
- **Advanced** (FSE, удалённо): полный доступ, Power Cycle стола, процедуры повышенного риска.
Функции: Power Cycle подсистем; Clear All; Override/Un-override (только для обслуживания, НЕ клиника); включение/отключение осей; Time Delay (прогрев); диагностика.

## 22. Утренний запуск и прогрев
1. Мониторы/интерком. 2. SF₆, уровень/температура воды. 3. Прогрев (напр. 6 MV × 500 MU) — выход на температуру, фиксация AFC. 4. Проверка дверного интерлока, лампы Beam-On, кнопки Beam-Off. 5. Прогрев всех энергий. 6. Выход/плоскостность/симметрия. 7. Лазеры/ODI/размер поля (±2 мм). 8. kV-MV пара для IGRT. 9. Защита от столкновений.
Частые утренние сбои: PUMP/FLOW (не прогрелась), BEL (AFC не зафиксирована), дверной, MLC не инициализирован.

## 23. Принципы сброса
«Интерлок сбрасывается только когда причина устранена». Алгоритм: идентификация (Event Log) → диагностика подсистемы → устранение → (при необходимости) Power Cycle → Clear All → все индикаторы зелёные → тест-пучок. Типы: LA (легко сбрасывается), AC (сначала устранить причину), DS (сервисный), HS (внешний источник).
